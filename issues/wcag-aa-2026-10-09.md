# WCAG 2.1 AA accessibility for faers.mobi + globalpatientsafety.com

## Summary

Harlan wants both public sites to conform to **WCAG 2.1 Level AA**. This file holds the 2026-10-09 baseline audit and the asks. Nothing on either site is legally blocked today. The goal is a defensible "WCAG 2.1 AA, with these known exceptions" statement for users and for pharma/hospital procurement.

Baseline captured 2026-10-09 06:20–07:00 ET from the Career box. faers.mobi build `api-f88bd019b098 src-3ae1844`, `X-FAERS-Through: 2025Q4`. globalpatientsafety.com is the nginx static site built by `scripts/build_static_site.R` in **this repo** (`harlananelson/globalpatientsafety`), and is rsynced to `/var/www/globalpatientsafety/`.

Tools: axe-core 4.x via `@axe-core/puppeteer` (tags `wcag2a, wcag2aa, wcag21a, wcag21aa, best-practice`), Lighthouse 12 (accessibility category only), and headless Chrome 154 at 1366×900. The Shiny pages were scanned only after the DataTable and timeline plot had rendered, which took 40–280 s per page. Lighthouse ran in **snapshot mode** on the rendered Shiny DOM and in navigation mode on the static pages.

**Automated tools catch only about 30–40% of WCAG issues.** Zero axe violations is necessary but not sufficient. The manual checks below are scripted probes, not a screen-reader test. Nobody has done a VoiceOver/NVDA pass yet.

Raw reports are in `issues/wcag-aa-2026-10-09/`:
- `axe/axe-<page>.json` holds violations and incomplete checks with full node lists. Passes and inapplicable checks are trimmed to rule IDs. `axe/axe-summary.json` holds the Shiny re-scan summary.
- `lighthouse/lh-<page>.json` holds the LHR, with screenshots stripped.
- `manual/manual-<page>.json` holds title, lang, landmarks, headings, tables, input labels, img alt, aria-live regions, and the first 25 Tab stops with focus styles.
- `scripts/` holds `scan.mjs` (axe + probes), `lhsnap.mjs` (Lighthouse snapshot for Shiny), `kb.mjs` (keyboard reachability of table rows), and `pages.json`.

## Asks (Linux)

Work in priority order: **critical, then serious, then moderate**.

1. **Fix every axe/Lighthouse violation listed above** on all 9 pages, plus the same patterns on any other template they share.
2. **faers.mobi specifics** (`harlananelson/faers-mobi`):
   - `lang="en"` on `<html>`. `page_navbar(lang = "en")` or `tags$html(lang=)` in bslib/htmltools both work.
   - Add a skip link ("Skip to search", then `#main`). Wrap content in `<main id="main">`. Add a single `<h1>`.
   - Give every input a visible `<label>` (or `aria-label` where a visible label would duplicate one): search, AND event, AND drug, trend and novelty selects, the readonly LLM link and brief textarea, and the DataTable column filters (via `aria-label="Filter <column>"` in an `initComplete`/`drawCallback`).
   - **Keyboard-operable rows.** Each row gets `tabindex="0"` (or a real `<button>`/link in the Drug or Event cell) that opens the pair view on Enter/Space and announces the selection. Prefer a link to `?drug=…&event=…`, so it also works without JS state.
   - Tables get a `<caption>` (it can be visually hidden) and `th scope="col"`.
   - Timeline plot gets a meaningful alt, e.g. "EB05/EWMA by quarter for tzield + Nausea, 2022Q1–2025Q4; data in table below". Add `aria-describedby` pointing to the pair-series table. If series differ only by colour, add line type or shape too.
   - Contrast of at least 4.5:1 for text (3:1 for large text and UI components). Override the Flatly `$success`/link green, `.alert-secondary`, `.alert-info`, muted text, the DataTables selected-row colours, and badges.
   - Add an explicit `:focus-visible { outline: 3px solid <≥3:1 colour>; outline-offset: 2px }` for links, buttons, inputs, `th[tabindex]`, and rows.
   - Async updates: keep the existing `aria-live` regions. Add `aria-busy="true"` on the table and plot containers while Shiny is recalculating (`shiny:recalculating` / `shiny:value` events). Announce the result count once per search instead of the whole table. Focus must never be lost on re-render.
   - Known/Novel/trend cues keep their text labels. Never reduce them to colour-only.
3. **globalpatientsafety.com specifics** (this repo: `scripts/build_static_site.R`, `articles/*.qmd`, `app/static/`):
   - Skip link plus `<main id="main">` in the builder's page shell and in the nav header it prepends to article HTML.
   - `aria-label="Toggle navigation"` on `.navbar-toggler`.
   - Fix heading order on the card grids (`h2` section, then `h3` card titles, or style the `h5` to look smaller).
   - Fix contrast: badge, disabled card, footer text, link colours, the Quarto theme's link and TOC green, and the gt heatmap text.
   - `fig-alt:` on every Quarto figure, plus a data-table equivalent for charts. Proper `<caption>`/`th scope` for gt tables (`gt::opt_table_lang`, or post-process valid `headers`/`id` pairs, or drop `headers=`). `tabindex="0"` on scrollable `pre`.
   - Re-render the affected articles, rebuild, and redeploy.
4. **Accessibility statement.** Publish `/accessibility` on **both** sites, linked from each footer. It must state the target standard (WCAG 2.1 Level AA), the conformance status (partial until the acceptance bar is met), known exceptions (e.g. PDF briefs, third-party DataTables/selectize widgets, legacy article charts if any remain), the feedback contact (**harlananelson@gmail.com**, since neither site shows a contact address today), the expected response time, and the date of last review.
5. **One automated gate.** Add a CI job or a monitor check that runs axe on the key pages and **fails on any serious or critical violation**:
   - GPS: a GitHub Actions job in `.github/workflows/site-checks.yml` that runs `@axe-core/cli` (or the `scripts/scan.mjs` here) against the built `static_site/` served locally, or against prod after deploy.
   - faers.mobi: a Shiny-aware check (wait for `.dataTables_wrapper tbody tr`) in `scripts/monitor_faers_mobi.sh` or a faers-mobi CI job against a local `shiny::runApp`. Report rule IDs and node counts in the deploy note.
6. **Do not** turn on the pay gate. It stays parked.
