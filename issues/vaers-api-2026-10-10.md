### Where the VAERS code lives (as far as GitHub shows)

- **Data:** `harlananelson/faers-pipeline` `R/download_vaers.R`, `R/parse_vaers.R`, `R/contingency_vaers.R`. Contingency is written in the FAERS schema: `rxcui` = VAERS `VAX_TYPE` (e.g. `COVID19`), `rxnorm_name` = `VAX_NAME` with manufacturer, `outcome_name` = MedDRA PT, `observed` = distinct (`vaers_id`, `rxcui`, `outcome_name`) tuples. Partitioned under `contingency/source=vaers/year=/quarter=`. Also writes `vaers_vaccine_dictionary.parquet` (`rxcui`, `rxnorm_name`, `n_reports`).
- **Stats:** `harlananelson/signal-compute` `R/compute_quarterly.R --source vaers`. Per quarter, a rolling 4-quarter window (default), cumulative prior (default), `min_observed` 3, `safetysignal::detect_all_methods(methods = c("gps","prr","ror","ic"))`, then EWMA (λ = 0.3) on `eb05` and `ic025` per (drug, event). The `drug` key is `coalesce(rxnorm_name, rxcui)`, so VAERS rows are keyed by **VAX_NAME + manufacturer**, not VAX_TYPE. Output `signals_vaers_v<date>.parquet`.
- **Deploy:** `harlananelson/signal-compute` `scripts/deploy_vaers_to_vps.sh` copies that parquet to `root@5.78.69.136:/srv/shiny-server/vaers-mobi/data/signals.parquet` (+ `vaccine_dictionary.parquet`) and touches `restart.txt`. App slug is `vaers-mobi`.
- **App source: not found on GitHub.** `gh search code` for `vaers-mobi`, `vaers.mobi`, `vaers.globalpatientsafety.com`, and the page title found no Shiny app repo. `aers-mobi` is FAERS + MAUDE, and `shinyserver` is empty. The app appears to exist only on the VPS. (Side note: the `faers-mobi` repo's `CLAUDE.md` overview describes a VAERS app with domain faers.mobi, which looks like a stale copy.)
- **nginx:** no VAERS server block in this repo or in `faers-mobi/scripts/*.nginx*.conf`. The VAERS block lives only on the VPS.

### What the live app says about its stats and data vintage

From the page HTML: "Bayesian and frequentist disproportionality analysis over CDC VAERS … data, 1990–2025", methods "GPS/EBGM, PRR, ROR, IC", "Peak EB05", and "EB05 is the 5th-percentile credible bound of the two-component Gamma mixture posterior … This is a direct posterior quantile, not the EBGM geometric mean." PRR is reported with Yates chi-squared (Evans 2001), ROR with a log-normal CI (van Puijenbroek 2002). The exact last quarter isn't visible without a Shiny session. Read it from the deployed parquet's max `quarter` and use that for the header.

## Asks (acceptance bars, all checkable live)

### 1. `GET /signals` for VAERS (vaccine × event)

Mirror the faers.mobi contract where it applies:

- Params: `vaccine=`, `event=`, `sort=` (`eb05` | `n` | `trend`), `order=asc|desc`, `limit`, `offset`, `min_eb05`, `min_n`, `format=json|csv|brief`. Unknown `format` → 400. Missing both `vaccine` and `event` → follow faers.mobi's behavior for a missing `drug`.
- `vaccine=` matches both `VAX_TYPE` (`rxcui`, e.g. `COVID19`) and `VAX_NAME` (`rxnorm_name`). Every row returns both as `vax_type` and `vax_name`, the raw string shown prominently, so a manufacturer- or product-specific row is never mistaken for the whole vaccine type (the GLP-1 lesson from #96). No silent merging across `VAX_NAME` strings. Summing n or averaging EB05 across them is forbidden.
- Row fields: `vaccine` (= `vax_name`), `vax_type`, `vax_name`, `event`, `n`, `eb05` (latest quarter's value, the same one the app shows as EB05; document whether it is raw or EWMA), plus `ebgm`, `prr`, `ror`, `ic025` if they're in the parquet. `trend`, `eb05_recent`, `eb05_prior` only if the app already derives them. If not, omit them and say so in `/api`. Do not invent a trend.
- Headers: `X-VAERS-Through: <max quarter in the deployed parquet>`, `X-VAERS-Build: api-<hash> src-<sha>`, `X-Total-Count`, `X-Limit`, `X-Offset`.
- `format=brief` states the filters it applied and how many rows it left out, the same as faers.mobi after #96.
- Every response (JSON field or header, plus brief/CSV text) carries the disclaimer: VAERS reports are voluntary and unverified; disproportionality is a hypothesis, not causation, and not an incidence rate.
